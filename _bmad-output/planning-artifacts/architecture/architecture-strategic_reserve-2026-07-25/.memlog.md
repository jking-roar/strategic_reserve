- (decision) Paradigm: Layered architecture with Game Engine, AI, and UI layers. Game Engine owns all rules and state; AI depends only on Game Engine; UI depends on Game Engine for state and AI for moves.
- (decision) Stack: Python 3.x with Tkinter for UI (built-in, lightweight). No external game frameworks to keep dependencies minimal.
- (decision) State ownership: Game Engine owns all game state (board, reserves, current player). UI is stateless - renders current state on demand. AI is stateless - receives state, returns move.
- (decision) Module boundaries: game_engine/ (rules, state, validation), ai/ (rudimentary, advanced implementations), ui/ (Tkinter rendering, input handling). No circular dependencies.
- (decision) Coordinate system: Board uses (0-5, 0-5) internal coordinates. Player perspective mapping handled at UI layer only. Game Engine uses absolute coordinates.
- (decision) AI interface: AI modules implement get_move(game_state, player_color) returning (row, col). Game Engine validates move legality before applying. AI cannot modify state directly.
- (decision) Group detection algorithm: Flood fill using orthogonal connectivity only. Game Engine provides get_groups(board, color) returning list of coordinate sets.
- (decision) Naming: snake_case for modules and functions (game_engine.py, get_legal_moves). PascalCase for classes (GameState, Board). Constants UPPER_CASE (BOARD_SIZE=6).
- (decision) Data structures: Board as 6x6 2D array (None for empty, 'RED'/'BLUE' for checkers). GameState as dataclass with board, reserves dict, current_player, winner.
- (decision) Error handling: Game Engine raises custom exceptions (IllegalMoveError, InvalidGameStateError). UI catches and displays user-friendly messages. AI never raises - returns None on error.
